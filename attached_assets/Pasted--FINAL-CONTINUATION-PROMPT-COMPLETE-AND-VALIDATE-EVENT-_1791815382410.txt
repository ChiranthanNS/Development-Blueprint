## 2. FIX DOCX TABLE EXTRACTION

The supplied DOCX is the primary event-data source. Its columns correspond to:

- Event Month
- Event Type
- Event Name
- Event Images
- Event Description

Review the existing parser in `extract.ts`, especially merged cells, month headings, row parsing, and embedded image handling.

Requirements:

- Import each valid event row once.
- Correctly inherit month and event type only when justified by the table structure.
- Preserve the original event type, event name, month, full description, source filename, and source wording.
- Support multiple JPG/PNG photographs associated with a single event.
- Preserve the correct photograph-to-event relationship.
- Handle merged cells, continuation rows, blank cells, multi-paragraph descriptions, and rows with missing dates.
- Do not invent missing facts.
- Do not create phantom events from table headings, layout fragments, or incomplete blank rows.
- Do not discard valid records merely because some details are missing.
- When a structured newsletter table has been recognized, do not independently import the same content a second time through general text extraction.
- Do not silently discard potential duplicates. Keep the duplicate review feature working.

Improve the extraction code with targeted changes. Avoid a complete rewrite unless the current implementation demonstrably cannot be repaired.
