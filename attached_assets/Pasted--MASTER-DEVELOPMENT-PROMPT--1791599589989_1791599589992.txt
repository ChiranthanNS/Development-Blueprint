============================================================
1. PROJECT BACKGROUND
============================================================

Faculty members are responsible for preparing departmental or
institutional newsletters containing information about events
conducted during an academic period.

Event information is usually available in different files such as:

- PDF documents
- Word documents
- Event posters
- Scanned documents
- Images
- Documents containing event photographs and descriptions

These files may contain:

- Event name
- Event description
- Date
- Time
- Venue
- Organizer
- Department
- Club/Chapter
- Participant information
- Event photographs
- Other event-related information

Currently, the faculty member manually reads these files,
identifies the type of every event, copies information and
photographs, organizes events category-wise, counts the events,
creates charts, and finally prepares the newsletter/report.

This is repetitive, time-consuming, and prone to errors.

============================================================
2. PROJECT OBJECTIVE
============================================================

Develop a web-based application that automates this workflow.

The application should allow a faculty member to upload one or
more files containing event information.

The application must:

1. Extract text from uploaded files.
2. Extract photographs/images.
3. Detect individual events.
4. Extract event information.
5. Classify each event using keyword-based analysis.
6. Calculate category scores.
7. Calculate classification confidence.
8. Identify ambiguous events.
9. Optionally use an AI/NLP API only as a fallback.
10. Display all classified events for human verification.
11. Allow events to be moved between categories using REAL
    drag-and-drop.
12. Allow events to be reordered.
13. Allow event information to be edited.
14. Allow photographs to be replaced, removed, or added.
15. Allow events to be added manually.
16. Allow events to be deleted.
17. Provide search and filtering.
18. Generate category-wise statistics.
19. Generate a pie chart.
20. Generate a professional PDF newsletter/report.
21. Allow the user to preview and download the PDF.
22. Clear temporary session data when the project ends.

6. FLEXIBLE DOCUMENT FORMAT
============================================================

Do NOT assume that every uploaded file follows the same layout.

The application must handle documents where:

- Event name is at the top
- Event name is inside a heading
- Event information is in paragraphs
- Date appears before/after description
- Photograph appears before/after text
- Multiple events exist on one page
- One event spans multiple pages
- Events are separated by headings
- Events are separated by whitespace
- Events are separated by numbering
- Events appear in posters
- Documents contain scanned pages

Use multiple signals to detect events:

- Headings
- Font/paragraph structure where available
- Dates
- Numbering
- Page boundaries
- Repeated formatting
- Paragraph boundaries
- Event-related keywords
- Image proximity
- Text proximity
- Document structure

Do NOT treat an entire document as one event if it clearly
contains multiple events.

============================================================
7. DOCUMENT TEXT EXTRACTION
============================================================

For PDF:

- Extract text using PyMuPDF/fitz or another reliable library.
- Preserve page numbers.
- Extract embedded images where possible.
- Preserve reading order as much as reasonably possible.

For DOCX:

- Extract paragraphs.
- Extract headings.
- Extract tables if present.
- Extract embedded images.
- Preserve document order.

For standalone images:

- Use OCR.
- Extract event-related text.
- Treat the original image as a possible event photograph.

17. KEYWORD WEIGHTING
============================================================

Example:

"challenge" = 1

"hands-on" = 2

The category score should be:

category_score =
sum of matching keyword weights

Rank categories by score.
