## 6. CORRECT NEWSLETTER DATA-FORMAT IMPORT

This is one of the highest-priority features.

The supplied Word document is a multi-page newsletter data table, not a simple document containing one event after another.

The existing application already has a structured table-import path in `extract.ts`. Preserve and improve that functionality.

The importer must recognize the source columns corresponding to:

- Event Month
- Event Type
- Event Name
- Event Images
- Event Description

The source table may use merged cells, repeated month headings, empty continuation cells, and rows containing multiple photographs.

### Required import behaviour

For every actual event record:

- Read the event month or reporting month.
- Preserve the source event type.
- Extract the event name where provided.
- Preserve the complete event description.
- Extract every supported embedded photograph.
- Preserve the association between the record and its photographs.
- Keep the original source wording available for review.
- Preserve the source filename for traceability.

Handle month headings correctly.

For example, a month heading such as `September 2025` may appear in a separate merged row rather than being repeated for every event.

Subsequent records should inherit that month when appropriate.

Likewise, if the document uses a merged event-type cell, subsequent related rows must inherit the type only when the source table structure supports that interpretation.

Do not merge unrelated events accidentally.

Do not create extra event records from incomplete layout fragments.

Do not drop valid records merely because a date is missing.

Do not replace blank values with invented information.

### Import diagnostics

After importing the Word table, display:

- Number of records imported.
- Number of photographs imported.
- Number of records requiring review.
- Unsupported image warnings.
- Extraction warnings.

When a table is recognized, use the structured table data rather than parsing the same entire document again as unstructured text and creating duplicate events.

If a record is duplicated in different input files, use the existing duplicate-review mechanism.

Never silently delete a potential duplicate.

## 11. CORRECT THE EVENT CLASSIFICATION SYSTEM

The application should continue using a configurable, weighted keyword engine as its primary classifier.

Do not make paid AI APIs a required dependency.

The existing categories include:

- Workshops
- Technical Talks
- Codeathons
- Hackathons
- Alumni Interactions
- Club Activities
- Outreach Activities
- Department Activities
- Student Achievements
- Faculty Achievements
- Placemental Success
- Other

Preserve these categories because they correspond to the reference newsletter.

### Classification rules

The system must:

- Normalize text before matching keywords.
- Support multi-word phrases.
- Give greater weights to category-specific terms.
- Calculate the scores for all configured categories.
- Identify ambiguous or low-confidence cases.
- Show the predicted category and why it was selected.
- Allow the faculty to override the predicted category.

### Important category distinctions

- A Codeathon is not automatically a Hackathon.
- A Hackathon is not automatically a Codeathon.
- A workshop involving coding should remain a Workshop if that is the intended source category.
- An outreach activity that also contains a workshop should not automatically lose its Outreach classification.
- A student's achievement at an external hackathon may belong in Student Achievements rather than the Hackathons section.
- A faculty publication or patent belongs in Faculty Achievements when that is the intended publication section.
- Placement records belong in Placemental Success.
- An alumni interaction should not be classified as an ordinary technical talk without appropriate justification.

Where the source document explicitly identifies an event type, prefer that source information over weak keyword guesses.

Do not assume that an ambiguous record has been classified correctly merely because it has a high numerical score.

Show “Needs Review” when necessary.
